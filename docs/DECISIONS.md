# 决策记录

## 使用方式

这里记录当前选择及改变条件。新增决定必须说明原因与验证方法；已被替代的决定保留状态，避免后来把暂时方案误认为不可变原则。实现状态以测试、代码和 [HANDOFF.md](HANDOFF.md) 为准。

## D01：自有持久状态

**采用。** Python ≥3.10 + FastAPI + SQLite 保持首版依赖少，并支持进程重启后恢复。供应商负责模型能力，项目负责工作区与任务真相。若出现多实例或写入并发瓶颈，再迁移数据库；迁移不得丢失版本和来源。

## D02：先云端语音

**已接通，体感待验证。** 采用Qwen、Fun-ASR、CosyVoice，避免依赖远端GPU。已做真实账号合成、回送识别和浏览器播放排程。固定声音服务伙伴体验；真实麦克风、主观自然度及完整对话延迟仍需体验，接口成功不能代替。

## D03：后台只交候选

**采用。** 对话继续时后台可能使用旧版本。候选保留基准版本和来源，由检查整合层决定是否合并。review 为默认，auto-apply 须显式开启。新增自动应用规则必须有冲突、重复提交和拒绝场景测试。

## D04：持续运行有边界

**采用。** 后台以持久任务、lease 和预算推进；可等待新信息或按计划再检查。持续运行不要求模型每秒推理。每次唤醒需说明目标、读取的状态和产生的变化，无变化也可安静结束。

## D05：自更新先可评估

**采用。** 从有证据的策略提案和固定回归开始，不开放任意运行时改代码。保留当前版本和失败案例。只有在新策略改善目标、且未破坏核心场景后才替换；失败则保留旧策略。

## D06：少量模块承载全局

**采用。** 围绕接口、工作区、后台、检查整合组织能力。新文件或依赖应能归属明确职责；跨职责变化说明输入输出和故障影响。先完整实现一个循环，再扩展搜索、教学和执行能力。

## D07：现成平台是强基线

**采用，依据 2026-10-30 复核。** Dots、Claude 新体验、Gemini Task 已覆盖大量核心功能，详见 [证据表](RESEARCH.md#三个商业参照的证据表)。自建首先验证可控工作区和交互方式，不竞逐通用 Agent 的连接器数量。若现成品同样好用，应减少自建范围。

## D08：验证可复利与伙伴感

**待验证。** 按四旅程比较分支丢失、有效新增依据、接续重述、拒绝后同类错误及审阅负担。熟悉声音和节奏另记个人偏好。若自建只改变外观而无可重复改善，缩小商业差异主张；不因单次喜欢就扩大功能。

## D09：商业主张保持条件

**假设，未验证。** 个人工具只需长期净收益为正；商业产品还要让其他人无需作者陪同也能复用、返回并愿付费。优先找持续研究或创作的人，用真实问题试用。卖结构与伙伴体验的可靠效果，不能把个人定制成本伪装成可规模化能力。

## D10：探索须服务持续问题

**候选方法。** 将触发原因、未解分支、一次探索预算和停止条件写清；每轮说明新依据改变了什么，没有增量可以不更新。方法本身可通过 skills 或提示在现成平台复现；先验证其价值，再判断是否需要专门运行底座。

## D11：最便捷复用路线

**优先用于价值验证。** 在已有资格的 Dots/Claude/Gemini 中选一个，维护一份问题文档与简短工作约定，配置后台任务，回来语音接续。拒绝案例交给可编辑 skills 和现成评估工具。先验证整套方法；不同时购买三家或重建其连接器。

## D12：最强自建路线

**保留为控制需求。** 自有版本化工作区保存问题、依据、候选和反馈；前台声音负责自然承接，后台模型独立探索；整合前比较版本和回归。先跑通四旅程，再拆更细模块。更强指可观察、可修改和可恢复，不保证模型更聪明。

## D13：最低对照实验

**待执行。** 同一真实问题跑三轮跨天循环：首轮半形成口述，次轮加入反证，第三轮口头汇报并打断、拒绝一次更新；随后重试并检查未见案例。对照最佳可用现成平台，保留输入和逐轮产物。单人结果只证明个人适配，不外推市场。

## D14：拒绝必须可解释

**候选改进。** 记录拒绝原因、影响范围与期限，先改对应检索、证据或表达策略，再用旧失败和未见案例比较。方法版本通过后才采用。暂时不需要不等于永久不感兴趣；拒绝按钮、写记忆和真正改善须分别验收。

## D15：汇报先保证忠实

真实口头汇报曾把旧候选里的MemFS推测当成当前未决问题。仅加提示仍未修好，因此默认汇报改为当前结构的确定性三段式，开放讨论继续用模型。先接受表达变化少一些，换取可核对、低延迟与零LLM汇报请求。

## D16：不同成本分开限额

轻量聊天120次/日，后台研究24次/日分别计数；后台不能耗尽交互额度。ASR1800秒、TTS12000计费字符不变。此设置用于试用，不能由次数推成金额硬上限；需从实际账单与使用节律再调。

## D17：输出失败不能假装还在说

无头Chrome的空白AudioContext也曾停在5.3ms，不能用首包和排程冒充可听延迟。已有PCM待播而音频时钟连续4秒不动时，明确失败并取消预取和队列，保留未播放状态。正常慢合成、暂停与打断另测；保护不能判断物理静音或人耳是否听见。

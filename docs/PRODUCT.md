# 产品约定

## 起点

Thinking Helper 帮用户通过表达进入思考状态，让值得继续的问题在离线期间得到推进，并将积累清楚地汇报回来。一次会话的价值是理解和行动有所进展；持续运行的价值是旧工作能成为新工作的基础。

## 需求来源

依据用户本轮原文及微信记录。原始附件为 `gpt thinking.zip`，由用户保管，不随仓库分发。以下为需求提炼；“activate 我自己”“侧重于形式”“少，精简，清晰明确”“保持全局观”来自用户表达，其他表述属于工程解释。

## 六项原则

1. 持续后台：离开界面后，授权的问题仍能推进。
2. 可复利结构：信息、判断和问题有稳定位置与来源。
3. 自然语音：允许停顿、改口和打断。
4. 清楚汇报：主线、当前进度和变化可以说清。
5. 可评估更新：局部修改可比较、可撤回。
6. 用户主体性：用户能查看、纠正、停止和决定方向。

## 伙伴体验

保持熟悉的声音、称呼和交流习惯，降低重新进入思考的负担。前台可以使用不同于后台的模型，但应共享可靠状态。安静陪伴、讨论、教学与汇报需要不同节奏；不能把每次表达强制变成待办事项。

## 最小完整循环

用户说出想法并改口 → 工作区保留当前问题与依据 → 后台按预算补充证据 → 检查后形成更新 → 用户听取简短汇报并纠正 → 下一次沿同一结构继续。每一步须可观察，不以“已反思”作为完成证据。

## 四个必须走通的旅程

1. 半形成口述：保留原意、备选解释和未定分支。
2. 离开以后：用新证据补充、反驳或缩小一个分支。
3. 再次回来：口头说明整体、变化和继续位置，允许打断。
4. 拒绝更新：理解拒绝理由，调整相关方法并检查效果。

这些是目标，不代表当前四项均已实现。

## 个人工具为何成立

一个人也可以因固定声音、熟悉节奏、数据可控和准确接续而受益，不要求每项能力独创。成立条件是收益超过配置、等待和审阅负担，并帮助自己更容易想清楚。若现成平台同样满足，应复用；独立部署本身不算价值。

## 商业产品为何仍待证明

除个人喜好，还要让其他目标用户无需作者陪同也能持续使用，并愿为增量再付费。候选价值是明确的长期结构、可靠接续和稳定伙伴体验。已有订阅的用户可以用提示与 skills 复现，因此必须比较实际结果，不能仅以功能组合收费。

## 拒绝不等于已经学会

拒绝可能因为方向无关、证据薄弱、表达不清或暂时不需要。应保留原因、适用范围和期限，只调整对应策略。本地已记录理由并交下一轮模型；这不证明策略已改善，远端与跨轮效果看 STATUS，不宣称自动变好。

## 范围与判断

首版验证上述循环。语音音质、自然打断、跨天连续性与后台发现的价值均需实测。暂不把任意运行时改代码、模型权重训练或无限自主扩展当作自迭代。候选功能应说明改善了哪项原则及如何验证。

## 成功信号

用户更容易开始表达，能指出自己的问题结构，隔天继续时少重复背景，并能纠正系统。记录误合并、错误记忆、抢话和无价值更新；使用时长、消息数量和生成文档数量不独立代表成功。

## 可证伪的差异

与最佳可用现成平台处理同一问题：旧分支丢失更少、有效新依据更多、接续需重述更少、拒绝后同类错误更少，同时审阅负担不增。若只换界面或声音，结果无改善，商业差异假设不成立；个人喜好仍可单独保留。

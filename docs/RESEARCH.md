# 研究依据与边界

## 阅读约定

核查日期：2026-10-30。官方文档确认公开能力，论文说明方法；均不代表本项目实测，也不是留存、付费意愿或需求成立的证据。访问资格、版本、计费和接口接入时仍需核对。以下“未证”指本轮资料未建立，不能解释为功能不存在。

## 首次实网反证

2026-10-30，主线实网验收报告：首轮任务虽然 completed，产物主要是计划，来源包含无关方法论页面，判定内容质量失败。完成任务和存在 URL 都不能证明研究推进。原始运行与复测结果由 `docs/STATUS.md` 记录，不能把该轮列为成功。

## 据此修正的检查

先获取相关官方网页正文，再提取有依据的新观点；结合已确认结构及待审候选，避免重复。没有新增的有据观点时不自动整合。搜索 checkpoint 用于恢复已完成步骤。这些是修正要求，是否落实及效果如何仍看实现与复测。

## 持续伙伴已有产品

OpenAI Dots 支持会话间工作、后台 Agent、自行休眠唤醒、持久笔记及通话。这确认持续伙伴有商业供给；不证明其默认能满足本项目的结构与汇报质量。访问资格和开放进度受限制。[官方概述](https://learn.chatgpt.com/docs/dots)

## 主动研究不同于记忆

Dots 会读取获准信息、关联旧工作并形成私有笔记；主动研究本身只读。通话使用的上下文也可能少于后台任务。由此要求本项目明确工作、记忆、汇报之间的状态交接。[官方边界](https://learn.chatgpt.com/docs/dots/tasks-and-memory)

## Claude 已变化的运行方式

Cowork 正与聊天合为统一体验，项目承接文件、指令和记忆。新定期任务在云端运行，关电脑仍可执行；10 月 6 日前的旧本地任务例外。因此撤回“Cowork 必须保持电脑开启”的笼统判断。[统一体验](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude) · [定期任务](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork)

## Claude 的连续性与声音

记忆按 Topics 可查看、编辑和删除，不能再把“可改记忆”视为本项目独有。新体验可在执行任务的对话里双向语音、开口打断及调用工具；旧 Cowork 界面仅听写，非英语支持仍为 beta。[记忆](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context) · [语音](https://support.claude.com/en/articles/11101966-use-voice-mode)

## Gemini 的直接反证

Google 8 月官方示例已包含：口述不成熟想法，后台整理成 Docs 大纲，跨天或周继续工作；Live 可以交办并口头简报。因而“语音表达加后台结构化”已有直接商业供给，不构成空白市场。[官方 Live 更新](https://blog.google/innovation-and-ai/products/gemini-app/productivity-features-gemini-live/)

## Spark 当前叫 Task

当前帮助页将 Spark 更名 Task：目标、事件或时间触发、可复用 skills、远端电脑和浏览器、Personal Intelligence 均可参与；生成 Docs 可在 Canvas 编辑。不是普通聊天的定时提示。账户需满足 Pro/Ultra、地区等要求。[当前能力与资格](https://support.google.com/gemini/answer/17094507?hl=en)

## 访问与成本不能混算

Dots 会话与委派工作额度分开；Claude 多界面共享使用限额；Gemini 按任务复杂度等计算用量。订阅不是无限后台，也不能用 API 单价估算。用户已有订阅时，自建多一套服务未必更便宜。[Dots](https://learn.chatgpt.com/docs/dots) · [Claude](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work) · [Gemini](https://support.google.com/gemini/answer/16275805?hl=en)

## 对自建差异的反证

三家已有持续任务、上下文和语音，Claude 与 Gemini 也有可编辑结构。公开文档未保证本项目想要的分支、未定判断、版本差异和精确口头接续；这只是待测机会。不能把“文档没写”当作竞品做不到，更不能以定时运行次数证明价值。

## 拒绝后的官方边界

Dots 可改持续规则，Claude 可改记忆，Gemini 可对话改 skills。Gemini 的“拒绝动作后停止”是执行控制，不能当作“否定观点后自动学习”的证据。本轮未找到三家默认将拒绝理由转为经回归验证的方法改进的明确说明。[Gemini skills](https://support.google.com/gemini/answer/17094296?hl=en) · [动作控制](https://support.google.com/gemini/answer/17094507?hl=en)

## 自迭代工具也有现成品

Anthropic 3 月更新的 skill-creator 可运行评估、基准和版本盲比，Claude.ai/Cowork 可用；OpenAI 也给出技能评估方法。它们支持复用“失败案例→改方法→比较”流程，但不证明无人监督的长期伙伴会持续变好。[Anthropic](https://claude.com/resources/articles/improving-skill-creator-test-measure-and-refine-agent-skills) · [OpenAI](https://developers.openai.com/blog/eval-skills)

## 哪些方法更值得保留

Anthropic 区分补足模型能力的 skills 与编码工作偏好的 skills：前者可能随模型进步失去必要，后者要检验是否忠实执行个人流程。由此把清楚汇报和结构约定做成可迁移方法；模型升级后也应测试能否删去旧技巧。[官方分析](https://claude.com/resources/articles/improving-skill-creator-test-measure-and-refine-agent-skills)

## 本地实现与真实效果分开

2026-10-30 后续复核，本地已补拒绝理由输入、API 持久记录及下轮提示；原话进入延迟整理任务，问题轮转并发现新来源，引用匹配正文，自迭代评估强制 not_run。它们是实现证据，远端部署和四旅程效果仍看 STATUS，不能宣告已学会。

## 价值判断仍有缺口

当前轮转依据尝试次数，不等于选中用户最关心或最有信息收益的分支。问题 ID 和原文匹配也不证明内容有用、引用蕴含观点或原话含义完整。优先由真实用户指出当前分支、审阅一次变化，再检查系统是否帮助他继续想，而非增添更多运行组件。

## 后台整理可以复用

OpenClaw 有分层记忆、Dreaming 后台整理和可检查的记录。它说明后台整理有现成实现；记忆合并仍不等于产生有价值的新洞见。本项目先将证据、候选与确认结果分开。[官方记忆机制](https://docs.openclaw.ai/concepts/memory)

## 调度不自动产生主动性

OpenClaw 的当前机制要求显式自动化；旧的对话承诺推断实验已移除。因此周期唤醒应有目标、预算和停止条件，不能把定时执行直接当作持续思考。[官方自动化机制](https://docs.openclaw.ai/automation)

## 中文语音的现成路径

百炼交互套件公开支持语音打断、模型配置、知识库及 CosyVoice；内置长期记忆按用户保存和召回。它降低 Demo 接入成本，但不替代本项目的版本、冲突和长期结构。[配置](https://help.aliyun.com/zh/model-studio/multimodal-app-configuration) · [记忆](https://help.aliyun.com/zh/model-studio/long-term-memory-api)

## 声音与交互须实测

CosyVoice 3.5 支持声音复刻与设计，音色需匹配目标模型。TTS 首包不代表完整对话等待，须测端点、识别、推理与播放。固定声音能否减少使用负担仍是体验假设；本项目实际结果查 STATUS。[官方模型能力](https://help.aliyun.com/zh/model-studio/tts-model/)

## 迭代需要外部结果

GEPA 使用执行轨迹、反馈和评估筛选提示改动；LongMemEval 区分时间、更新、多会话推理等记忆能力。由此采用固定场景验证提案；论文任务收益不能外推为长期伙伴必然变好。[GEPA](https://arxiv.org/abs/2507.19457) · [LongMemEval](https://arxiv.org/abs/2410.10813)

## 前沿一：把交互与工作解耦

[Realtime-Venus](https://github.com/inclusionAI/Realtime-Venus)公开9B全双工模型与异步Harness：边听边说，后台结果回到原会话，再选择何时口头交付。独立推理需CUDA。值得借鉴的是双循环与“完成≠已播”，当前不能据此声称本机能低成本运行。

## 前沿二：话轮也值得用小模型

[LiveKit](https://docs.livekit.io/agents/logic/turns/turn-detector/)音频话轮检测支持中文，另有附和与打断处理。它比只设静音阈值更贴近自然交互。现版仍是简单规则；下一步应拿同一组停顿、附和、改口录音对照，再决定是否引入。

## 前沿三：改协调方法而非只换大模型

[DuplexAgent-RSI](https://arxiv.org/html/2610.11299v1)把协调拆成可改模块，用失败轨迹定向修补，同案例配对比较并检查独立保护集。论文仍承认感知与话轮错误不一定能靠规则修好。本项目可借鉴评估闭环，不照搬模块数量或宣称已实现自动优化。

## 当前路线的判断

先用Fun-ASR、Qwen-Flash、CosyVoice保证可检查、可替换的中文链路；复杂整理用Qwen-Plus后台执行。若真麦克风显示停顿/抢话是主要损失，先换话轮层；若整合质量差，先改证据与评估。用失败决定升级，避免先堆模型。

## 常驻不等于不停推理

Dots会决定何时休眠与唤醒。可复用的原则是持久责任、事件与观察、按价值激活计算。本原型目前为固定小时检查与日额度，尚非自适应探索。若几轮没有增量，应降低频率或换问题，而不是用更多摘要维持活跃表象。

## 语音成本的量级

按北京区当前[价格](https://help.aliyun.com/zh/model-studio/model-pricing)，1800秒Fun-ASR约0.594元；12000计费字符CosyVoice-Flash约0.96元。两项合约1.55元，未计模型、搜索及其他调用。它是按标价的估算，不是账单或金额硬上限。

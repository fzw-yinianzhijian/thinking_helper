# Thinking Helper · 当前判断

## 真正要解决什么

帮我更容易开始、持续并接回自己的思考。表达可以零散，系统要保留原意、未确定的分支与整体线索；回来时能清楚向我汇报，减少重述与整理负担。语音是自然入口；跨时间持续工作的责任和承接成果的结构才是核心。

## 最重要的循环

说出未成熟想法 → 保留原话并形成待审分支 → 离开后围绕问题继续查证、反思、探索 → 把有价值变化接回原结构 → 口头接续并允许纠正。没有增量可以安静；不会把又写一篇摘要当作理解增长。

## 为什么仍值得做

Dots、Claude、Gemini已覆盖大量语音与后台能力，功能组合不是新机会。个人自建可获得固定声音、自有状态与可修改节奏；商业差异须靠更少分支丢失、更低接续和审阅负担证明。当前没有付费意愿或长期效果证据。

## 工程怎样保持清楚

只保留四个职责：交互接收表达；工作区保存版本、分支与证据；后台按责任持续推进；检查整合把候选变成可解释更新。前台和后台共用状态。内容版本与方法版本分开；复盘建议、实际修改和评估记录也分开。

## 已落地与未证明

已做远端持久队列、来源正文读取、版本冲突隔离、待审更新、中文语音链路、原话整理与拒绝反馈；实际状态见[STATUS](STATUS.md)。自然度、真实端到端延迟、跨天收益仍需体验。模型会犯错，原文匹配和单测均不等于语义正确。

## 下一步只检验一个闭环

同一问题连续使用三轮：零散口述、加入反证、离开后回来汇报并打断、拒绝一次更新再重试。与已有平台比较分支保全、重述、审阅时间和同类错误。先决定这个使用方式是否有价值，再扩模型、插件或商业范围。

## 给你的可调整项

优先实际体验声音、停顿与汇报长度；默认每小时研究、轻量交互120次、后台24次模型请求、12000个TTS计费字符与1800秒ASR日预留，候选先审。体验后再调频率与自动整合边界。研究依据在[RESEARCH](RESEARCH.md)，后续接手从[HANDOFF](HANDOFF.md)进入。

# 架构约定

## 最小技术栈

Python ≥3.10、FastAPI 与 SQLite。持久状态由本项目管理，模型供应商可替换；首轮连接云端 Qwen、Fun-ASR 与 CosyVoice。远端 Node 12 环境不作为新前端工具链基础，首版浏览器界面避免构建依赖。

## 四个职责

| 职责 | 负责 | 交付给下一层 |
| --- | --- | --- |
| 接口 | HTTP、语音、会话与取消 | 有序输入、明确请求 |
| 工作区 | 项目结构、版本与来源 | 可读取的当前事实 |
| 后台 | 调度、检索与生成候选 | 带依据的版本化提案 |
| 检查整合 | 校验、审阅、合并与汇报 | 可解释的变更及结果 |

## 源码入口

`app/main.py` 和 `app/static/` 负责交互，`app/voice.py` 连接云语音。`app/core.py` 同时承载工作区和事务检查整合。`app/engine.py` 调度，`app/providers.py` 产出模型候选。四职责是边界，不要求强拆为四个独立服务。

## 工作区是共同依据

界面和后台读取同一持久工作区。记录问题、证据、判断、决定与待审候选，区分用户陈述和模型推断。摘要属于可重建的视图。每个项目有递增版本，已确认内容不被晚到结果静默覆盖。

## 前台与后台分开推进

聊天保存事件；用户通过“补充或纠正当前结构 → 记入结构”提交后才增加工作区版本。原话进入合并整理任务，再交待审分支；后台持有启动版本，完成后交候选，不阻塞聊天。语音打断取消当前回应；停止后台需另行操作。

## 候选合并

候选保存基准版本、变化内容、依据和状态。版本不符即标记 stale，保留历史但不能应用，应基于新版本重做。默认人工 review；显式启用 auto-apply 后也只应用检查通过的当前版本内容候选。方法建议不自动应用。

## 持久任务

任务入 SQLite 后再执行。领取任务使用有期限的 lease；重启后可恢复过期领取。主题默认每小时检查；每次执行有次数、时间或调用预算。重复领取不得重复合并结果。失败、重试与预算耗尽都应成为可读状态。

## 预算边界

首轮每日 LLM 24 次、TTS 12,000 计费字符、ASR 1,800 秒。调用前原子预留，失败也可能保留预留。所有任务共享额度，按上海时区次日重置；预算不足的后台任务延后。当前记录预留单位，尚无 token 明细或人民币硬上限。

## 模型边界

供应商适配负责鉴权、流式数据和错误归一。核心工作区不依赖供应商会话 ID。云端请求失败时保留输入与项目状态，给出明确错误。密钥留在服务端；数据库和日志不应保存密钥或完整鉴权响应。

## 自迭代

先记录“观察到的问题 → 证据 → 修改提案 → 评估结果”。候选策略通过固定场景回归后再替换当前版本。模型生成提案不等于批准；首版不允许后台任意修改运行中的程序。回归场景见 [EVALUATION.md](EVALUATION.md)。

## 仍需验证

持久任务、冲突与取消已有确定性回归；真实云协议、浏览器麦克风、远端恢复及长期成果价值仍需独立验证。此文档描述边界，实际检查及未测项统一查 `docs/STATUS.md`，不从设计推定通过。

## 可追溯的研究单位

planning.py选择未决问题与verify/counterexample/update操作。候选声明evidence/hypothesis/reframe及问题、原话ID；有据更新须附实读原文。非事实推进仍有价值，但必须未确认并人工审阅。来源和ID匹配不证明语义关系。

## 运行版本与内容版本

主题version表示理解变化；runtime_revision是app源码指纹。方法提案绑定后者且evaluation初始not_run。evaluation.py只运行固定检查并保存真实结果；接受提案不会改策略，checks_passed也不证明因果改善或回退成功。

## 交互竞争的隔离

切主题、停止、刷新都有代际检查，迟到结果不能覆盖当前界面或发到新主题。语音当前句与最多一句预取分别取消；已播收据独立写回原主题。口头报告读取当前结构和真实运行合同，外部文档能力不等于本项目已接入。
